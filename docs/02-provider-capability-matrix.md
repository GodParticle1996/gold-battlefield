## Verification notes (what was actually checked, 2026-08-13)

1. **Binance — streams (official docs, `web-socket-streams.md`):** endpoints `wss://stream.binance.com:9443` / `:443`, market-data-only `wss://data-stream.binance.vision`. Limits: **5 inbound control messages/s per connection** (exceeding → disconnect; repeated → IP ban), **1024 streams per connection**, **300 connections / 5 min / IP**, **24 h connection lifetime** with `serverShutdown` notice, server **ping every 20 s → pong within 60 s**.
   - `aggTrade` payload verified: `a, p, q, f, l, T, m, M` — `m` = *buyer is maker* → aggressor is **sell** when `m=true`, **buy** when `m=false`.
   - `bookTicker` (real-time best bid/ask with `u` updateId) and partial depth (`depth5/10/20` @ 1000 ms/100 ms) payloads verified.
   - **No checksum on spot depth streams.** Correctness uses the documented local-book procedure: snapshot `lastUpdateId` → buffer deltas → discard events with `u <= lastUpdateId` → gap detection when `U > local+1` → full resync. This is the authoritative sequence protocol.
2. **Binance — geo-restrictions:** multiple independent sources (2022–2026) confirm `api.binance.com` returns **HTTP 451 for US, Canada, the Netherlands, and sanctioned territories**; account access from those regions is prohibited. Deployment region therefore determines availability — our gateway must run in a permitted region, and the fallback chain (Kraken → Swissquote → replay → simulation) absorbs failures.
3. **Kraken — rate limits (support.kraken.com article 206548367, updated 2026-08-10):** public REST endpoints limited **by IP** (Trades/OHLC additionally by pair); calling at **≤ 1 call/s stays within limits**; exceeding throttles for a few seconds (longer if abuse continues). Private/trading limits are irrelevant to this app.
4. **Kraken — book checksum (official guide `websockets/book-checksum-v2`):** every v2 book update carries a **CRC32 checksum**; validation is optional and can be periodic. Checksum always computed over the **top 10 price levels** regardless of subscription depth. Algorithm verified: asks top-10 sorted low→high, then bids top-10 high→low; per level strip `.` from price and qty, strip leading zeros, concatenate `price+qty`; concatenate asks-string + bids-string; CRC32 → unsigned 32-bit int. `qty=0` deletes a level; book must be truncated to subscribed depth after each update.
5. **Kraken — feeds:** spot WS v2 documented (`spot-websocket-v2/book`); v1 public unauthenticated `book`/`trade`/`ticker` documented on support.kraken.com; trade feed carries taker `side`. XAUT/USD and PAXG/USD are listed spot pairs.
6. **Swissquote:** the keyless BBO endpoint was fetched live on 2026-08-13 and returned valid JSON: three platforms, spread profiles, `bid`/`ask` (≈ 4365/4366 USD per oz), millisecond `ts`. No authentication. Polling-limited, quote-only, no documented SLA.
9. **Kraken — LIVE VERIFICATION (2026-08-13):** the WS v2 adapter ran against the live feed (`XAUT/USD`): snapshot + updates delivered, best bid/ask tracked the market (spread ≈ $0.10), 0 gaps/0 resyncs, trades parsed with taker side. **Checksum finding:** the live feed transmits price/qty as JSON numbers (the official guide shows strings); a systematic search (30+ formatting variants incl. raw/fixed-8/colons/alternating/pre-update) failed to reproduce any live checksum. Per spec §3 the adapter does NOT fake validation — it emits full-state snapshots per message (self-healing), and the doc-verified string algorithm remains unit-tested (reproduces the official example).
10. **Swissquote — LIVE VERIFICATION (2026-08-13):** the MODE D adapter polled the endpoint (5 s cadence) and produced reference-price events (bid/ask/midpoint ≈ $4,356/oz) with `isDelayed: true`, stale detection after 3 failed polls, and backoff — verified via `verify-live.ts reference`.
12. **Coinbase — RESEARCH + LIVE VERIFICATION (2026-08-13, keyless):** REST `ticker` + `book?level=2` returned real PAXG-USD data (≈ $4,358/oz). WS `level2_batch` delivered 1 snapshot + 36 `l2update` deltas + a `match` in 6 s. **Finding:** `l2update` deltas carry NO sequence numbers (only `time`) — the adapter buffers deltas until the WS snapshot, applies in stream order, and treats every reconnect as a full resync (documented limitation; no fabricated gap detection). `match.side` = taker side (aggressor). Adapter integrated as MODE A and verified through the gateway: 1 snapshot + 77 deltas / 15 s, spread +$0.07, 0 resyncs, CVD honestly hidden (no trades in window).
13. **Gemini — RESEARCH (2026-08-13, keyless):** REST `pubticker` + `book` returned real PAXGUSD data (bid ≈ $4,336 / ask ≈ $4,362). WS `marketdata` stream delivered 61 `update` events in 6 s with successful subscription. Trade events document `taker_side`/`maker_side`.
15. **Gemini — INTEGRATION + LIVE VERIFICATION (2026-08-13):** the MODE A/B adapter was built against captured live shapes and verified through the gateway. **Findings:** (a) the first `update` message is the FULL initial book (change events with `reason: 'initial'`, `socket_sequence: 0`); (b) `remaining` is the CUMULATIVE level size (absolute set semantics — updates 5–6 at one price showed 1.0958 → 4.6371), so the book sets (not accumulates) and `remaining: 0` deletes; (c) **`socket_sequence` counts every socket message including heartbeats — using `?heartbeat=true` caused false gaps (4 gaps/20 s); without it, sequences are contiguous (0 gaps over 195 updates)** → the adapter connects without heartbeats and relies on its stale timer; (d) trades/block-trades ride inside `update.events` (parsed defensively; `takerSide` → aggressor, unknown otherwise). Verified via `verify-live.ts gemini`: 126 deltas applied contiguously (updateId 126), 0 resyncs, snapshot first; 45 s forced-reconnect run (reconnect at 20 s + 40 s) re-synced both times with 0 resyncs and `applied: true`. Note: the ~$24–30 spread is the REAL Gemini PAXG book (thin market), not an artifact.
14. **Bitstamp — RESEARCH (2026-08-13, keyless):** REST `ticker` + `order_book` require the **lowercase slug** `paxgusd/` (uppercase 404s). Both returned real data (≈ $4,358/oz). WS v2 subscriptions succeeded (`diff_order_book_paxgusd` + `live_trades_paxgusd`) with data events flowing; `live_trades` carries a buy/sell side flag per docs.
16. **Bitstamp — INTEGRATION + LIVE VERIFICATION (2026-08-13):** the MODE A/B adapter was built against captured live shapes and verified through the gateway. **Findings:** (a) `diff_order_book` sends CHANGED levels only — the first `data` message was a pure diff (`bids: []`), so the initial book MUST come from the REST endpoint (adapter fetches it on connect, Binance-style, buffering diffs meanwhile); (b) `0.000000` amount deletes a level; (c) no sequence numbers on diffs → no gap detection; the adapter mitigates with a **periodic full-book resync every 5 min** (self-healing, documented) plus fresh REST snapshot on every reconnect; (d) the server may send `bts:request_reconnect` (infra restart) — handled by reconnecting. Verified via `verify-live.ts bitstamp`: REST snapshot + diffs applied (spread ≈ $2.10 — tighter than Gemini's ~$25), 0 resyncs, `applied: true`; 40 s forced-reconnect run (closes at 15 s + 30 s) re-synced both times with 0 resyncs. Trades not captured live (PAXG volume ≈ 3 oz/day); parse unit-tested against the documented `type` 0/1 shape.

## Policy applied (spec §3)

- No endpoint URL, symbol, quota, price, or licensing term is asserted without the checks above; anything pending is marked ⚠️ and isolated behind adapter + env-var configuration.
- **Correctness mechanism per provider (verified):** Binance spot = sequence-gap protocol (`U`/`u`/`lastUpdateId`, no checksum); Kraken spot v2 = CRC32 top-10 checksum (optional periodic validation); Coinbase = no delta sequence numbers → full-snapshot-on-reconnect (self-healing), documented in the adapter; Gemini = per-socket `socket_sequence` gap protocol (no heartbeat param); Bitstamp = REST snapshot + diff feed with **periodic full-book resync** (no sequences — drift self-heals every 5 min) and a reference price derived from the REST book's best bid/ask. All implemented in the order-book package and unit-tested with fixtures.
- The gateway never logs secrets or full authorization headers; `.env.example` ships placeholders only.
- Adapters validate configuration at startup (`validateConfiguration()`) and fail loudly with a clear message if a provider is misconfigured.
